# 主题雕塑创作会审

本仓库保存主题雕塑会审链服务的领域资料、事件契约与最小实现，覆盖史实主张、设计会审、材料试验、安装放行与铭牌发布的完整可追溯链路。

## 领域规则

- **主张绑定证据**：每条史实主张绑定证据引用、证据版本、确定性等级（`confirmed` / `probable` / `disputed` / `refuted`）与允许引用范围（`label` / `design_only` / `internal`）。只有确凿且可入铭牌的主张才能进入铭牌。
- **设计版本明确采用内容**：每个构件声明引用哪些主张，每条引用标明是史实（`fact`）还是艺术推断（`inference`）。相邻设计版本可**继承未变化结论**，但已变化的主张必须重新签署。
- **签署职责互不代办**：
  - 历史顾问（`historian`）只确认史实，闸门 `historical`；
  - 艺术委员会（`art_committee`）只决定是否接受推断，闸门 `artistic`；
  - 结构人员（`structural`）只对材料试验与安装安全签署，闸门 `structural` / `installation`。
  - 闸门按序推进，**并发签署不得越过前序条件**；继承也须由对应角色在新版本亲自签署。
- **证据变化精确锁定构件**：新档案只推翻某人物服饰年代时，按构件实际引用分流，整版设计不退回：
  - 未制作 → `COMPONENT_HELD` 暂停，待更正后的设计版本采纳后恢复；
  - 已制作 → `COMPONENT_DISPOSITIONED` 形成处置方案（替换 / 留用 / 改造），替换产生后继构件；
  - 已安装 → `INSTALLATION_CORRECTED` 后续更正，**原安装与原放行决定保留**，铭牌追加 `LABEL_CORRECTED` 更正记录。
- **只追加、可重放**：事件标识、发生时间、版本一旦写入不得原地改写，更正永远产生后继事件。同编号请求（`request_id`）只有内容哈希一致才算重放，内容不同返回 `REQUEST_CONFLICT`。

## 追溯

`traceComponent(componentId)` 从单一构件即可反向获得：

```
构件 → 主张（事实/推断）→ 证据版本链与确定性
     → 历史顾问 / 艺委会签署 → 材料批次与试验（含批次取代关系）
     → 安装放行与安装事件 → 铭牌发布与历次更正 → 安装后更正记录
```

## 模块

- `contracts/domain.schema.json`：事件信封契约（事件类型、聚合类型、可选元数据）。
- `data/sample.json`：中文样例记录。
- `src/constants.js`：事件、聚合、确定性、引用范围、角色、闸门、构件状态枚举。
- `src/events.js`：不可变事件信封、事件标识、请求内容规范化哈希。
- `src/projection.js`：纯函数事件归约、待办队列、构件追溯。
- `src/chain.js`：命令分派器，承载全部业务规则与签署闸门。
- `src/log.js`：只追加 JSONL 事件日志，支持中断后重放恢复。
- `src/service.js`：内存校验 + 日志持久化的服务装配。
- `tests/`：场景化自动化测试。

## 本地检查

```bash
npm test     # node:test，11 项
npm run build # 全部源文件语法检查
```

测试覆盖四类规定场景：**局部推翻**（三分支精确处置 + 未引用构件不受影响）、**结构材料替代**（失败批次挂起、替代批次通过后放行）、**安装后更正**（原决定保留、铭牌追加更正）、**中断恢复**（从 JSONL 重放后待办顺序与事件逐位一致）；另含角色闸门越权、并发越序、幂等重放冲突与契约枚举一致性。
